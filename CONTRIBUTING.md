# Contributing

## Workflow

1. Create a focused branch from `main`.
2. Keep each change scoped to one problem or feature.
3. Add or update tests for behavior that changes.
4. Run the strongest available checks locally before opening a pull request.
5. Describe the root cause, implementation, validation results, and any environment-specific limitation in the pull request.

## Standards

- Do not disable meaningful validation to make CI pass.
- Do not add tests that only assert implementation trivia or fake coverage.
- Keep documentation aligned with observed behavior.
- Treat performance, usage, and reliability numbers as measured results; label estimates and benchmarks explicitly.
